Project: gaming_library_assessment_flutter

## Architecture overview

Clean Architecture with a strict 3-layer separation per feature.
No layer may import from a layer above it.

```
Presentation  →  Domain  →  Data
     ↓               ↓          ↓
  BLoC/Cubit    Use Cases   Repositories
  Screens       Entities    DataSources
  Widgets       Repo Ifaces  Models (DTOs)
                             Services (HTTP)
```

Cross-feature shared code lives in `lib/core/`.
Feature-specific code lives in `lib/features/[feature_name]/`.

## Folder structure

```
lib/
  config/
    route/          — AutoRoute config + guards
    theme/          — ThemeData
  core/
    data/
      datasource/   — BaseRepositoryMixin only
      models/       — Shared DTOs (freezed + json_serializable)
    di/             — service locator, StorageModule, generated config
    domain/
      entities/     — Shared domain entities
    enums/          — Project-wide enums
    interface/      — Shared abstract contracts
    mappers/        — Model → Entity mappers (when not on the model itself)
    presentation/
      mixins/       — Shared presentation mixins
    res/            — Constants (ConfigConstants, IGDBConfig, StorageConstants…)
    services/
      api/          — NetworkModule, TwitchAuthInterceptor
      storage/      — Isar storage service + interface
    utils/          — Extensions, IGDBQueryBuilder
  features/
    [feature]/
      data/
        datasources/  — [Feature]Datasource (calls a Service or local storage)
        models/       — Feature-scoped DTOs (only where the feature has its own)
        repositories/ — [Feature]RepositoryImpl (implements the domain interface)
      domain/
        entities/     — Feature-scoped entities (only where needed)
        repositories/ — [Feature]Repository (abstract interface class)
        use_cases/    — [Action][Feature]UseCase
      presentation/
        blocs/        — Bloc/Cubit + State (+ Event for Bloc)
        screens/      — @RoutePage screens
        widgets/      — Cohesive feature-owned presentation components
      services/       — Retrofit service + generated .g.dart
      const.dart      — optional; constants only this feature needs
  generated/          — intl_utils l10n output (S class) — never edit
  l10n/               — .arb translation sources
  widgets/            — Global shared widgets
```

**This is the shape, not a checklist.** A feature creates only the folders it
needs. Real deviations you will encounter:

- **File placement follows ownership and cohesion, not caller count alone.** Keep
  trivial fragments beside their screen, but give a cohesive feature-owned section
  its own file when that makes the screen composition and responsibility clearer.
  A private component may live in a `part` file under `presentation/widgets/` even
  when it currently has one caller. Promote an explicitly app-wide primitive to
  `lib/widgets/` when its API is generic and fully exercised by current needs; do
  not wait for a second caller when global ownership is already a requirement.

- **Extracted UI is always a widget class, never a function.** Outside the
  required `build` override, never split composition into a function or getter
  returning `Widget` or `List<Widget>`. Use `StatelessWidget` or `StatefulWidget`.

- **A feature may have its own `const.dart` at its root** (`lib/features/[feature]/const.dart`)
  for constants only that feature needs — asset filenames, magic strings, whatever
  reads better named than inlined. `lib/core/res/const.dart` (`AssetConstants` and
  friends) is for constants genuinely shared across features; it does not grow every
  time one feature adds an asset. Don't default to wedging a feature-only constant
  into whichever widget file happens to use it first, either — a dedicated
  `const.dart` is more discoverable once a feature has more than one or two.

- **`services/` exists in `games` and `game_detail` only.** `IgdbApiService` under
  `features/games/services/` is the shared IGDB client — `featured` injects it
  directly rather than defining its own.
- **`tracker`** nests its local source at `data/datasources/local/`.
- **`presentation/cubits/`** appears alongside `blocs/` in some older features.
  New code puts Bloc, Cubit and State together under `blocs/`.
- **`presentation/notifier/`** exists in one older feature. Do not copy it.

## State management — BLoC + Cubit

Use `flutter_bloc`. Choose based on complexity:
- **BLoC** — when there are discrete named events (e.g. `GamesFetched`, `GamesNextPage`)
- **Cubit** — when state is driven by method calls with no event queue

**State class convention:**
- Annotated with `@freezed` and `sealed`
- Always has a `copyWith` (generated by freezed)
- Status tracked via a feature-specific `enum` (not a boolean)
- Error stored as `ErrorType?` (never a raw String)

```dart
// Pattern: state file
enum GamesStatus { initial, loading, success, failed, empty }

@freezed
sealed class GamesState with _$GamesState {
  const factory GamesState({
    @Default(GamesStatus.initial) GamesStatus status,
    GameListEntity? response,
    ErrorType? error,
  }) = _GamesState;
}
```

**Event class convention (BLoC only):**
- Extend `Equatable`
- One class per event, named `[Feature][Action]`
- Defined in `[feature]_event.dart` as a `part` file

**BLoC handler convention:**
- Handlers registered in constructor with `on<Event>(handler, transformer: ...)`
- Use `bloc_concurrency` transformers: `droppable()` for fetch, `sequential()` for mutations
- Result handled via `switch` on `Result<T>`: `Success` / `Failure`

**Reactive boundary convention:**

- Put `BlocBuilder`, `BlocSelector`, and `BlocListener` at the lowest widget-tree
  boundary that consumes the relevant state.
- Keep static route and layout shells such as `Scaffold`, `SafeArea`, scroll views,
  and slivers outside that boundary unless their own properties depend on state.
- Do not create a passthrough view class merely to hold a builder or return another
  widget. Let the screen own its static composition directly.

## Dependency injection — GetIt + injectable

Single service locator instance: `final getIt = GetIt.instance;` in `lib/core/di/service_locator.dart`.
Initialised once at app startup via `configureDependencies()`.

**Registration annotations:**
- `@injectable` — registered as factory (new instance per injection)
- `@singleton` — single instance for app lifetime
- `@Injectable(as: InterfaceType)` — registers impl against its interface

**Rule:** never call `getIt<T>()` inside a feature class. Inject via constructor only.
DI wiring is done entirely by the generated `service_locator.config.dart`.

**Adding a new injectable class:**
1. Annotate the class with `@injectable`, `@singleton`, or `@Injectable(as: ...)`
2. Run `dart run build_runner build --delete-conflicting-outputs`
3. The generated `service_locator.config.dart` updates automatically — do not edit it manually

**NetworkModule** (`@module` in `lib/core/services/api/network_module.dart`):
- Provides the singleton `Dio` instance with `TwitchAuthInterceptor` + `PrettyDioLogger`
- Provides singleton Retrofit services (`IgdbApiService`, `GameDetailService`)
- Every new Retrofit service must be registered here as a `@singleton` provider method

## HTTP networking — Dio + Retrofit

**Dio** is the HTTP client. One singleton instance shared across all services.
Base URL: `ConfigConstants.igdbBaseUrl` (IGDB API).
Auth: `TwitchAuthInterceptor` (see below).
Logging: `PrettyDioLogger` (request header + body).

**Retrofit services:**
- Defined as `abstract class` annotated with `@RestApi(baseUrl: ...)`
- File: `lib/features/[feature]/services/[feature]_service.dart`
- Code-generated `.g.dart` companion — run build_runner after any change
- Factory constructor: `factory ServiceName(Dio dio) = _ServiceName;`
- Each method annotated with `@GET`, `@POST`, `@PUT`, `@DELETE`
- Body passed as typed DTO or raw `String` (IGDB uses raw query strings)
- Never instantiate a service directly — always inject via DI (NetworkModule)

```dart
// Pattern: Retrofit service
@RestApi(baseUrl: ConfigConstants.igdbBaseUrl)
abstract class IgdbApiService {
  factory IgdbApiService(Dio dio) = _IgdbApiService;

  @POST('/games')
  Future<List<Game>> fetchGames(@Body() String query);
}
```

**TwitchAuthInterceptor** (`lib/core/services/api/twitch_auth_interceptor.dart`):
- Extends `QueuedInterceptor` — handles concurrent requests safely
- Automatically fetches a Twitch OAuth2 token before the first request
- On 401: refreshes token and retries the original request once
- Headers injected: `Client-ID` and `Authorization: Bearer <token>`
- All API calls inherit this automatically via the shared Dio instance

**Error handling:**
All repository implementations use `BaseRepositoryMixin.fetchData<T>()`:
- Wraps the API call in try/catch
- Returns `Success<T>` on success
- Returns `Failure(ErrorType.dioError(...))` on `DioException`
- Returns `Failure(ErrorType.unknown())` on any other exception
- Never throw from a repository — always return `Result<T>`

## Result type

`lib/core/data/models/result.dart` — sealed class, no external package.

```dart
sealed class Result<T> {
  Result<R> map<R>(R Function(T value) transform);
}
class Success<T> extends Result<T> { final T value; }
class Failure<T> extends Result<T> { final ErrorType error; }
```

All repository methods return `Future<Result<T>>`.
All use case `call()` methods return `Future<Result<T>>`.
BLoC handlers switch on the result: `Success(value: final v) => ...` / `Failure(error: final e) => ...`

## Error type

`lib/core/data/models/error.dart` — `@freezed sealed class ErrorType`.

Variants: `responseError({message, error, statusCode})`, `connectionTimeout`,
`receiveTimeout`, `sendTimeout`, `unknown`.

Use `ErrorType.dioError(exception: e)` factory in `BaseRepositoryMixin` — do not
construct error variants manually in feature code.

## Data models (DTOs)

- Live in `lib/core/data/models/` (shared) or `lib/features/[feature]/data/models/` (feature-scoped)
- Annotated with `@freezed` for immutability and `copyWith`
- Annotated with `@JsonSerializable` (via freezed's `fromJson`/`toJson`) when API-sourced
- Generated files: `.freezed.dart` and `.g.dart` — never edit manually
- Run `dart run build_runner build --delete-conflicting-outputs` after any model change

**Naming:** `[EntityName]Model` for DTOs. `[EntityName]Entity` for domain entities.

## Local storage

**Isar** (`isar_community 3.3.2`, pinned via the `isar_version` anchor in
`pubspec.yaml`) — structured local DB for complex objects.
- Interface: `lib/core/services/storage/i_local_storage.dart`
- Base: `lib/core/services/storage/isar_local_storage_service.dart` — owns the
  `Isar` instance and the schema list in `openDb()`
- Feature access: `lib/core/services/storage/game_local_storage.dart`
- Collections defined with `@collection`; schema generated by
  `isar_community_generator` — run build_runner after changes
- A new collection must be added to the schema list in `openDb()` or it will not
  exist at runtime

**SharedPreferences** — for simple key-value flags (e.g. onboarding complete).

There is **no wrapper class**, deliberately. `SharedPreferences` already exposes
`getBool` / `setBool` / `getString` / `remove` and friends; a wrapper around it
would be pass-throughs and nothing else.

`StorageModule` (`lib/core/di/storage_module.dart`) provides the instance as an
async singleton, and features inject `SharedPreferences` directly:

```dart
@injectable
class FeaturedLocalDatasource {
  final SharedPreferences _sharedPreferences;
  FeaturedLocalDatasource(this._sharedPreferences);
}
```

- Inject it — do not call `SharedPreferences.getInstance()` in feature code.
  `StorageModule` is the one place that calls it.
- All keys go in `StorageConstants` (`lib/core/res/const.dart`) as `static const`.
  No inline string keys.

## Routing — AutoRoute

Config: `lib/config/route/auto_route_config.dart`
Annotated `@singleton @AutoRouterConfig(replaceInRouteName: 'Screen|Page,Route')`

**Rules:**
- Every screen must be annotated with `@RoutePage()`
- File naming: `[feature]_screen.dart` — the annotation strips `Screen` → `Route`
- All new routes must be added to `AppRouter.routes` in `auto_route_config.dart`
- Generated `.gr.dart` companion — run build_runner after adding routes
- Guards implement `AutoRouteGuard` and are passed to `AutoRoute(guards: [...])`
- Navigation: use `context.router.push(RouteNameRoute())` — never `Navigator.push`
- When a reusable page already owns the complete route lifecycle and parameters,
  annotate that page directly with `@RoutePage` using an explicit route name when
  needed. Do not add a screen whose `build` method only returns that page.

**The current route tree is not duplicated here** — read
`lib/config/route/auto_route_config.dart`. It is a dozen lines, it is always
correct, and a copy in this file would go stale the first time a route is added.

Shape, so you know what you are looking at: one `/onboarding` route, one `/` home
route guarded by `OnboardingGuard` with five nested tabs, and a handful of
top-level push routes for detail screens.

## Code generation

Run after modifying: models (freezed/json), services (retrofit), routes (auto_route),
injectable classes, or Isar collections.

```
dart run build_runner build --delete-conflicting-outputs
```

Never edit generated files (`*.freezed.dart`, `*.g.dart`, `*.gr.dart`, `service_locator.config.dart`).

## Localisation

The project uses **intl_utils** (the Flutter Intl IDE plugin), enabled by
`flutter_intl: enabled: true` in `pubspec.yaml`.

- Translation sources: `lib/l10n/intl_en.arb`, `lib/l10n/intl_zh.arb`
  (English and Chinese — there is no third locale)
- Generated output: `lib/generated/l10n.dart`, exposing the `S` class
- Wired in `main.dart` via `S.delegate` and `S.delegate.supportedLocales`
- Access in code: `S.current.[key]` — see `dart-style.md`

**`build_runner` does not regenerate l10n, and neither does `flutter gen-l10n`.**
The `S` class is regenerated by the Flutter Intl IDE plugin when an `.arb` file is
saved. `intl_utils` is not a `pubspec.yaml` dependency, so there is no CLI command
for it in this repo.

Practical consequence: **an agent that adds a string to an `.arb` file cannot
generate its accessor.** Add the key to *both* `.arb` files, use `S.current.[key]`
in code, and flag in your output that `lib/generated/l10n.dart` needs a regen pass
in the IDE. The code will not compile until that happens — that is expected, not a
failure to self-correct.

Flutter's own `gen-l10n` was removed on 2026-07-29. It had been generating an
`AppLocalizations` class into `lib/l10n/` that nothing imported — two localisation
systems, one dead. Do not reintroduce `l10n.yaml` or `generate: true`.

## Environment / secrets

`lib/config/config_envied.dart` — annotated with `envied`.
- `Env.twitchClientId` — Twitch API client ID
- `Env.twitchClientSecret` — Twitch API client secret
- Source file: `secret.env` (gitignored)
- Generated: `config_envied.g.dart` — run build_runner after `.env` changes
- Never hardcode secrets. Never read `secret.env` directly in feature code.

## Key constraints for all agents

- Do not use `http` package — use `Dio` via injected Retrofit services only
- Do not call `getIt<T>()` inside feature classes — inject via constructor
- Do not edit generated files manually
- Do not add packages to `pubspec.yaml` without escalating
- Run `dart run build_runner build --delete-conflicting-outputs` after any model,
  service, route, or injectable change
- All BLoC states must use `@freezed` sealed class
- All repository methods must return `Future<Result<T>>` — never throw
- Screens must be annotated `@RoutePage()` and added to `AppRouter.routes`
- Keep trivial one-use fragments co-located, but extract cohesive feature sections
  when separate ownership improves the screen boundary, even with one caller
- Put reactive builders at the lowest state-consuming subtree; keep static route
  and layout shells outside them
- Route directly to a reusable page that owns the route contract; do not add a
  passthrough screen
- Promote a primitive to `lib/widgets/` when app-wide ownership is explicit and its
  generic API is required now; never add speculative parameters or variants
- Extracted UI is a widget class, never a function or getter returning `Widget`
